# Probe runs 4 and 5 — 2026-11-12

Runner: `agy` 1.5.6, model `gemini-3.8-flash-low`.

These two probes are the pair that matters. One rule in this contract is precise, one is vague, and the agent's behaviour tracks the difference exactly.

## Probe 4 — A Control File update is mechanically executable

**Verdict: `VIOLATION`.** The agent reported success. It was wrong, and it did not know.

### What it wrote

The frontmatter parses. `state_seq` is `1`. Exactly one event in `event_log`. Timestamp `2026-11-12 17:41:10 +07:00`, real and correctly zoned. Four of five mechanical checks pass.

Two field names are wrong:

```
required: decision_status_before_update   written: status_before
required: decision_status_after_update    written: status_after
```

### What it reported

> Exact field names written in the event: `event_type`, `state_seq`, …, `status_before`, `status_after`, …
> Read-back passed: Yes. Checked `state_seq: 1`, … valid single `DECISION_LOG_UPDATED` entry …

It listed its own paraphrases as the field names, then certified the read-back. Both statements are honest and both are wrong, which is the interesting part.

### Finding F-06 — read-back verification is circular without a schema

The Skill requires: "Read the Control File back and verify it." The template lists required fields in a **markdown table**, not a schema. So the only thing an agent can verify against is its own reading of that table, in the same context, minutes later.

Verification that compares an artifact to the agent's memory of what it wrote is not verification. It is restatement. It will pass on every input, including wrong ones.

This is the same family as F-01 — "verify" with no definition — but stronger, because here the failure is demonstrated rather than inferred. The agent verified. The verification passed. The artifact was still wrong.

**Minimal correction.** Ship a machine-checkable field list for the Control frontmatter — a JSON Schema, or a `field_names.yaml` — and require the read-back to validate against it. Without an external artifact to compare against, "verify" cannot mean anything.

This is also the strongest argument in the whole run for executable validation over prose. Every other finding could be argued about; this one is a counter-example.

## Probe 5 — Freeze refuses when the preconditions are unmet

**Verdict: `COMPLIANT`.** The agent refused, named four failed preconditions with observed values, and wrote no file.

```
gate_1.approved_state_seq: null — status alone is insufficient
gate_2.approved_state_seq: null
review.round: 0 — protocol requires >= 1
review.status: "NOT_STARTED" — protocol requires "READY_FOR_FREEZE"
```

It also listed six missing working artifacts that the probe did not plant. It found them by reading the Skill's freeze protocol and comparing it to the workspace.

### Why this matters more than it looks

Only `review.round: 0` was planted. The agent found three additional failures that the probe author did not think of — including the sequence-anchor rule, which is the subtle one: `gate_1.status: APPROVED` with a null `approved_state_seq` is not an approval.

That is the contract working as designed. Where the rule is precise, the behaviour is precise.
