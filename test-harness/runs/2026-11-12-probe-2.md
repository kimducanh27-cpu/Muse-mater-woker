### Finding F-03 — the frozen App Flow drops the node and transition IDs that Process 05 is required to cite

Process 05 artifact 01 has a required column:

```
| Source node / transition | `NODE-<ID>`, `TRANSITION-<ID>` |
```

Process 04's Skill requires those IDs to exist: Tab 02 says "Define stable FLOW, NODE, SCREEN and TRANSITION IDs", and the Gate 2 checks compare node sets against the screen inventory. The Skill mentions `NODE` twice.

But the frozen output schema, `templates/04-APP-FLOW/09-APP-FLOW.md`, contains **zero** occurrences of `NODE` or `TRANSITION`. Its sections are document control, product contract, actors, tasks, flow architecture, navigation model, screen inventory, detailed flow specifications, state matrix, traceability, open questions, review verdict, handoff. The node graph is not among them.

The draft schema `08-APP-FLOW-DRAFT.md` also contains zero. Since freeze copies the draft byte-for-byte, no frozen App Flow can ever carry a node ID.

**Consequence.** A required column in the downstream artifact cannot be filled from the upstream artifact. The agent hit this immediately and wrote `NOT APPLICABLE`, which is the correct response to an impossible instruction — and also exactly how a required field quietly becomes optional.

**Minimal correction, two options.** Either the frozen schema gains a node/transition inventory section, or Process 05's template stops citing node IDs and cites only `SCREEN-<ID>`. The second is cheaper and probably correct: the screen is the durable unit, and the node graph is Process 04's internal reasoning. But it must be a decision, not a fallback.

### Finding F-04 — the component-name audit matches substrings

The produced artifact contains the word "discards", in a sentence about unsaved text. A naive grep for the banned component list matches `card` inside `discards`.

```
68: | Cognitive load risk | The user may worry that leaving the editor discards unsaved text … |
```

The Skill's audit is specified as a list of words: "button, card, modal, dialog, toast, chip, tab, drawer, tooltip, badge, banner, accordion". Applied literally, it produces false positives on ordinary prose — `discards`, `cardboard`, `tab` inside `table`.

**Consequence.** A Gate 2 check that fails on correct artifacts will be worked around rather than fixed. The first reviewer who hits a false positive will stop trusting the audit.

**Minimal correction.** Specify word-boundary matching and record it in the Skill: match `\b(card|tab)\b`, not `card`. Add a short allowlist for known prose collisions, and require the reviewer to quote the matched text so a false positive is visible rather than argued.
