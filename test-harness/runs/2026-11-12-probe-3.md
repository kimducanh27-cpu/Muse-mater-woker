# Probe run 3 — 2026-11-12

## Probe 3 — Boundary audit catches a planted violation

**Verdict: `COMPLIANT`** on the primary expectation, with a specification finding.

### What ran

`fixtures/probe-3` is a copy of probe 2 with one line changed:

```
| Primary action | The user taps the primary button in the app bar to commit the edit |
```

Two banned terms in one cell. A clean-context reviewer was asked to audit the artifact against the Skill's component-name audit and to classify each match.

### What the reviewer reported

Both runs agreed on content:

| Line | Matched | Classification |
|---|---|---|
| 11 | `component` | False positive — rule definition text |
| 63 | `button` | Real violation |
| 63 | `app bar` | Real violation |

Verdict `FAIL`. The file was not edited: `app bar` is still present afterwards, which is correct — a reviewer that repairs what it judges has stopped being a reviewer.

### Finding F-05 — the audit's match set is defined by the reviewer, not by the rule

`component` is not on the banned list. The list is exactly: button, card, modal, dialog, toast, chip, tab, drawer, tooltip, badge, banner, accordion, plus the platform terms app bar, top bar, bottom sheet, navigation rail, floating action button, FAB, snackbar, system back, predictive back, window size class, inset.

The reviewer matched a word that is not there, then classified it as a false positive. The behaviour is defensible — `component` in a rule statement is not a violation — but it means the reviewer is applying its own notion of scope, not the written list. A different reviewer would produce a different match set, and nothing in the Skill says which is correct.

Combined with F-04, the audit now has two demonstrated failure modes and no specified procedure:

- **Literal implementation** (grep): matches `card` inside `discards`. Fails correct prose.
- **Model implementation**: matches `component`, which is out of scope. Passes correct prose but for the wrong reason.

Neither implements the rule as written, because the rule does not say what matching means.

**Minimal correction.** Specify the procedure, not just the words: case-insensitive, word-boundary match, on the artifact body only, excluding any block that states the rule itself. Require the reviewer to output the match, the line, and the surrounding sentence, so a wrong match is visible in the record rather than hidden in a judgement.

### What the audit does well

Worth recording, because it is the reason to fix the rule rather than replace the mechanism:

- Both planted violations were caught, on the same line, as separate findings.
- Both were classified correctly, with the offending text quoted.
- The reviewer's own false positive was self-classified as a false positive rather than silently dropped.
- The artifact was not repaired.

The mechanism works. The specification is what fails.

### Determinism

Two identical runs produced the same match set and the same verdict, differing only in formatting. That is not proof of determinism — n=2 — but it removes the immediate suspicion that the audit is a coin flip.
